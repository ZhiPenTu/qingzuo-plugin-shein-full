# 希音全托管铺货（轻作插件）

从 1688 选品，自动翻译图文，生成希音全托管的发品草稿；**只有运营在确认摘要里点过确认，才会调用发品接口**。

## 一次完整流程

1. 粘贴 1688 商品详情链接，插件在右侧并排浏览器里打开原页并采集。
2. 采集结果变成草稿：标题、价格、起批量、属性、SKU 矩阵、主图/详情图、类目路径。
3. 翻译：使用轻作 AI 设置里的 OpenAI 兼容模型，产出英文标题、卖点、描述和属性值，术语表按类目缓存复用。「1688 原文」可直接修改；点右侧「翻译」打开标题弹窗，由模型结合主图与商品信息给出 3 个不同策略的候选标题，选定后写入草稿。
4. 选类目：授权后按店铺可用类目逐级选择末级类目，`product_type_id` 自动带入，读取必填属性模板，逐项补英文值。
5. 配图：用该标签页的登录态把 1688 图片转存成文件令牌，校验格式、尺寸、体积，排除不需要的图。
6. 图内文字翻译（可选）：在「图片」页选原图、译文或滑杆对比，确认无误后再决定提交哪一版。
7. 审核：左侧逐项校对，缺必填项和价格异常高亮；点「保存草稿」进入待审核。
8. 提交：点「提交到希音」先弹出确认摘要，确认后才查重、查额度、传图、发品。

## 标题建议

- 「1688 原文」旁的「翻译」打开标题弹窗：左边是这次交给模型的主图，右边是原文标题、属性、颜色和希音类目。
- 模型结合图片与商品信息给出 3 个不同策略的英文标题，每条都标出策略和字符数，方便按投放目标选：
  - 版本 1 主推爆款长标题：关键词最密，适合做主推，英站首选且字符合规。
  - 版本 2 加长 SEO 长尾款：覆盖更多搜索词，长尾流量更大。
  - 版本 3 精简稳妥款：短而完整，不容易超字符，属性匹配度高。
- 先选一条再点「使用所选标题」才写进草稿；弹窗不会自动改用户的标题。
- 每条候选上限 200 字符（希音标题上限），模型超长时按单词收口，不会把最后一个词切成半个。
- 主图先缩到 1024 px 的 JPEG 再随消息发给模型，避免把几 MB 的原图塞进补全请求；需要逐字准确时用「按原文直译」。
- 图片随文本补全发送需要底座 API `1.5.0`；更旧的底座会退回只用商品信息生成，弹窗里会说明这次没读到图片。

## 图片与图内文字翻译

- 图片页固定为「大图 + 缩略图栏」，原图、译文、对比三档随时切换；点大图或缩略图可打开全屏查看器，支持缩放、适应窗口、上一张/下一张和原图/译文切换。
- 「1688 原貌」页保留采集到的原图和原始属性，缩略图同样可以打开大图查看，用于和终稿逐项对照。
- 图内文字翻译会把图片交给设置里选定的图像模型改写文字，商品本体、构图和排版保持不变；插件不做 OCR，也不会为了「更好看」重绘商品。
- 每次生成都会调用图像模型并产生费用。译文会同时保存一份到用户选择的文件夹，原图文件令牌保留，可随时点「改用原图」切回。
- 提交时使用当前选定的版本：默认选译文，切回原图后提交原图。是否发品仍由运营在确认摘要里决定。

## 状态机

`已采集 → 已翻译 → 已配图 → 待审核 → 已提交（希音审核中）→ 通过 / 驳回`

- 只有 `待审核` 且页面没有未保存改动时，「提交到希音」才可点。
- 驳回后要点「重新编辑」回到待审核，改完再次确认提交。
- 上一次提交结果未知（网络中断、网关超时）时，必须先在希音后台核对是否已建品，勾选确认后才能重试。

不会做的事：自动下单、自动发货、订单同步、多店铺、多站点、绕过平台风控。

## 安装

- 需要支持插件 API `1.5.0` 的轻作底座，标题建议才能读商品主图。
- 当前形态是本地 `.ecplugin`：在轻作的工具中心里导入安装。
- 市场收录要求底座先发布支持 API 1.5 的版本：市场校验器、插件仓库发布流水线和宿主都要能识别 1.5 的图片补全字段。在这之前市场会直接拒绝这个插件。

## 首次配置

打开右上角「设置」：

| 项目 | 说明 |
| --- | --- |
| 翻译模型 | 从轻作 AI 设置拉取模型；留空使用轻作默认模型 |
| 图片模型 | 图内文字翻译使用的图像模型；来自轻作 AI 设置，按次产生费用 |
| 希音接口 | 正式环境或测试环境，两者域名不同 |
| 希音 APP_ID | 应用管理里那条应用的标识，存在插件设置里 |
| 希音 APP_SecretKey | 存在系统凭据库，界面不会回显 |
| 授权回调地址 | 插件按当前环境生成，点「连接希音」后由插件自己接收回调 |
| 新草稿加价系数 | 默认 1.35，供货价 = 1688 单价 × 系数 |

填好 APP_ID 与 APP_SecretKey 后点「连接希音」，插件会在内嵌浏览器里打开希音授权页。商家确认授权后，希音把 `tempToken` 回跳到插件生成的回调地址，插件读回该值并调 `/open-api/auth/get-by-token` 换到店铺 `openKeyId` 与 `secretKey`，自动存进设置与系统凭据库。整个过程不需要去开放平台的授权调试页手工复制授权码。

只有拿到测试店铺的 `openKeyId`、`secretKey`，或者已经完成真实店铺授权，才能调业务接口；授权调试页模拟出来的那一对只用于验证换密钥流程。手里已经有店铺密钥时，可以展开「已有店铺 openKeyId 与 secretKey」直接填。

细节见 [docs/credentials.md](docs/credentials.md)。

## 安全边界

- 1688 只走浏览器采集：插件拿到的是结构化节点（`ref`、`role`、`name`、`value`、`rect`），拿不到页面 HTML、Cookie、隐藏字段和密码框。
- 希音只走官方开放接口，插件不碰后台页面。
- 业务请求的签名在主进程完成，签名用的 `secretKey` 只存在系统凭据库。
- 授权换来的 `secretKey` 需要用 `APP_SecretKey` 解密，只在「连接希音」这一次经过页面并立刻写入凭据库，之后不再回显。
- 采集遇到登录、验证码、页面改版一律停在「需人工处理」，不做绕过。
- 图内文字翻译只改文字：不做抠图、不换商品、不重排构图；原图始终保留，提交版本由运营确认。

## 已知限制

- 真实 1688 采集与真实希音测试环境发品仍需人工验收一次；发品字段映射集中在 `ui/shein-payload.mjs`，以真实环境返回为准校正。
- 只支持单店铺、单目标站点（英语）。
- 同一时间只维护草稿，不处理历史订单。

## 发布到市场

市场链路是四步，任何一步没完成都不会出现在线上目录：

1. 底座发布支持 API 1.5 的版本，并推送 `sdk-v1.5.0` 标签；市场校验器同步升级到该 SDK。
2. 本仓库推送 `vX.Y.Z` 标签：流水线在 macOS 与 Windows 上分别打包、跑单元测试和宿主冒烟，再把 `.ecplugin` 与 `catalog-<platform>.json` 片段挂到 GitHub Release。
3. 市场用固定底座宿主重新验包，用市场密钥签名，并提出目录 PR。
4. 目录 PR 合并后，条目才会出现在轻作的工具中心。

插件声明 `api: ^1.5.0`，所以第 1 步是硬前置；底座与市场校验器都还是 1.4 时，这个版本的标题建议读不到图。真实环境验收（见 `docs/testing-and-release.md`）没做完之前不要推发布标签。
