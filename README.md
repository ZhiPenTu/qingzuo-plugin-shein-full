# 希音全托管铺货（轻作插件）

从 1688 选品，自动翻译图文，生成希音全托管的发品草稿；**只有运营在确认摘要里点过确认，才会调用发品接口**。

## 一次完整流程

1. 粘贴 1688 商品详情链接，插件在右侧并排浏览器里打开原页并采集。
2. 采集结果变成草稿：标题、价格、起批量、属性、SKU 矩阵、主图/详情图、类目路径。
3. 翻译：使用轻作 AI 设置里的 OpenAI 兼容模型，产出英文标题、卖点、描述和属性值，术语表按类目缓存复用。
4. 选类目：填写希音末级类目与 `product_type_id`，读取必填属性模板，逐项补英文值。
5. 配图：用该标签页的登录态把 1688 图片转存成文件令牌，校验格式、尺寸、体积，排除不需要的图。
6. 审核：左侧逐项校对，缺必填项和价格异常高亮；点「保存草稿」进入待审核。
7. 提交：点「提交到希音」先弹出确认摘要，确认后才查重、查额度、传图、发品。

## 状态机

`已采集 → 已翻译 → 已配图 → 待审核 → 已提交（希音审核中）→ 通过 / 驳回`

- 只有 `待审核` 且页面没有未保存改动时，「提交到希音」才可点。
- 驳回后要点「重新编辑」回到待审核，改完再次确认提交。
- 上一次提交结果未知（网络中断、网关超时）时，必须先在希音后台核对是否已建品，勾选确认后才能重试。

不会做的事：自动下单、自动发货、订单同步、多店铺、多站点、绕过平台风控。

## 安装

- 需要支持插件 API `1.4.0` 的轻作底座。
- 当前形态是本地 `.ecplugin`：在轻作的工具中心里导入安装。
- 市场收录要求底座先发布支持 API 1.4 的版本：市场校验器、插件仓库发布流水线和宿主都要能识别 1.4 的文本 AI 字段。在这之前市场会直接拒绝这个插件。

## 首次配置

打开右上角「设置」：

| 项目 | 说明 |
| --- | --- |
| 翻译模型 | 从轻作 AI 设置拉取模型；留空使用轻作默认模型 |
| 希音接口 | 正式环境或测试环境，两者域名不同 |
| 希音 openKeyId | 开放平台应用的标识，存在插件设置里 |
| 希音 secretKey | 存在系统凭据库，界面不会回显 |
| 新草稿加价系数 | 默认 1.35，供货价 = 1688 单价 × 系数 |

细节见 [docs/credentials.md](docs/credentials.md)。

## 安全边界

- 1688 只走浏览器采集：插件拿到的是结构化节点（`ref`、`role`、`name`、`value`、`rect`），拿不到页面 HTML、Cookie、隐藏字段和密码框。
- 希音只走官方开放接口，插件不碰后台页面。
- 签名在主进程完成，`secretKey` 不进入插件页面。
- 采集遇到登录、验证码、页面改版一律停在「需人工处理」，不做绕过。
- v1 不改图：不做抠图、不翻译图内文字，保持商品原貌。

## 已知限制

- 真实 1688 采集与真实希音测试环境发品仍需人工验收一次；发品字段映射集中在 `ui/shein-payload.mjs`，以真实环境返回为准校正。
- 只支持单店铺、单目标站点（英语）。
- 同一时间只维护草稿，不处理历史订单。

## 发布到市场

市场链路是四步，任何一步没完成都不会出现在线上目录：

1. 底座发布支持 API 1.4 的版本，并推送 `sdk-v1.4.0` 标签；市场校验器同步升级到该 SDK。
2. 本仓库推送 `vX.Y.Z` 标签：流水线在 macOS 与 Windows 上分别打包、跑单元测试和宿主冒烟，再把 `.ecplugin` 与 `catalog-<platform>.json` 片段挂到 GitHub Release。
3. 市场用固定底座宿主重新验包，用市场密钥签名，并提出目录 PR。
4. 目录 PR 合并后，条目才会出现在轻作的工具中心。

插件声明 `api: ^1.4.0`，所以第 1 步是硬前置；真实环境验收（见 `docs/testing-and-release.md`）没做完之前不要推发布标签。
